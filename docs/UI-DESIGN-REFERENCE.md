# 주몽 UI 디자인 참고: 알파스퀘어에서 추출한 원칙

## 목적과 출처

- 참고 서비스: <https://alphasquare.co.kr/>
- 확인일: 2026-09-25
- 참고 범위: 한 화면에서 관심 종목·차트·분석 기능을 함께 다루는 정보 구조, 금융 서비스다운 정보 밀도, 읽기 쉬운 수치 표현
- 제외 범위: 알파스퀘어의 화면·문구·상표·이미지·아이콘·정확한 배치를 그대로 복제하는 일

알파스퀘어는 관심 종목, 차트, 스마트 기능을 별도 화면 전환 없이 함께 보는 3단 화면 구성을 소개한다. 주몽은 이 구조의 **정보를 빠르게 훑는 방식**만 참고하고, 초보자의 가상투자 복기라는 제품 목적에 맞게 더 단순하게 만든다.

## 주몽 화면의 우선순위

1. 이 서비스가 가상 현금만 쓰는 학습용 투자 장부임을 항상 보인다.
2. 금액, 수량, 수익률의 기준일·단위·출처를 읽기 전에 이해할 수 있게 한다.
3. 사용자가 한 화면에서 계좌 상태와 보유 종목을 비교할 수 있게 한다.
4. 데이터가 없거나 계산할 수 없으면 빈 칸과 임의 숫자 대신 이유와 다음 행동을 보여 준다.
5. 미래 작업의 차트·관심 종목·의사결정 기록은 실제 데이터와 작업 범위가 준비됐을 때만 추가한다.

## 정보 구조

### 데스크톱: 정보가 많은 금융 화면의 느낌

기본 폭 1440px 이상에서는 아래처럼 세 영역을 고려한다. 단, 각 영역의 데이터가 현재 작업에 없으면 빈 위젯을 만들지 않고 해당 영역을 생략하거나 본문 안에 안전한 안내를 표시한다.

| 영역 | 역할 | 현재 또는 미래 데이터 예시 |
|---|---|---|
| 상단 헤더 | 서비스명, 가상투자·읽기 전용 상태, 평가 기준일 | 주몽, "가상 학습 투자 장부", 가격 기준일 |
| 좌측 보조 영역 | 빠른 종목 탐색과 상태 요약 | 미래의 관심 종목, 종목별 등락률 |
| 중앙 핵심 영역 | 계좌 요약, 포트폴리오, 차트 또는 핵심 분석 | 가용 현금, 평가금액, 보유 종목 표, 미래의 일봉 차트 |
| 우측 보조 영역 | 사용자의 최근 행동과 유의사항 | 최근 가상 주문, 손실 한도 경고, 판단 메모 |

- 중앙 영역은 항상 가장 넓게 둔다. 표, 차트, 종목 상세처럼 비교가 필요한 정보가 여기에 온다.
- 좌·우 영역은 독립적인 카드 모음이 아니라, 현재 선택 또는 평가 기준을 이해하도록 돕는 보조 정보여야 한다.
- 주문 입력, 실제 주문, 자동 매매, 실시간 가격은 현재 제품 경계 밖이다. 해당 작업에서 허용하지 않으면 버튼·빈 입력 폼·가짜 시세를 만들지 않는다.

### 작은 화면: 정보 손실 없이 순서만 바꾸기

- 1024px 이하: 보조 영역을 중앙 본문 위·아래로 옮기거나 한 열로 전환한다.
- 768px 이하: 계좌 요약 카드는 2열 또는 1열, 표는 항목명과 값이 함께 보이는 세로 카드형 행으로 전환한다.
- 375px 이하: 헤더 → 경고/기준일 → 계좌 요약 → 보유 종목 → 최근 주문 순으로 한 열에 쌓는다.
- 모바일에서 표의 가로 스크롤만으로 핵심 값을 숨기지 않는다. 각 값에 종목, 수량, 원가, 기준 종가처럼 명시적인 label을 남긴다.

## 시각 원칙

### 색과 수치

- 밝은 회백색 배경 위에 흰색 패널을 사용하고, 경계선은 약하게 구분한다.
- 기본 텍스트와 제목은 navy 계열, 링크·현재 선택 상태는 절제된 blue 계열을 사용한다.
- 수익은 emerald 계열, 손실은 red 계열을 쓰되 색만으로 상태를 표현하지 않는다. `이익`, `손실`, `변동 없음` 같은 텍스트와 `+`/`-` 부호를 함께 표시한다.
- KRW는 정수와 천 단위 구분 기호를 사용한다. 수량은 `주`, 수익률은 `%`, 가격은 `KRW`를 표기한다.
- 중요 수치는 왼쪽 설명·오른쪽 값 또는 열 단위 정렬을 일관되게 유지한다. 숫자를 장식용 큰 글자로 과도하게 키우지 않는다.

### 밀도와 계층

- 하나의 화면에서 중요한 수치를 비교할 수 있는 수준의 정보 밀도를 유지하되, 카드마다 두꺼운 그림자·큰 여백·큰 제목을 반복하지 않는다.
- `header`, `main`, `section`, heading, `table`, `caption`, `th scope` 등 semantic HTML을 사용한다.
- 계좌 요약은 작은 핵심 지표 카드, 보유 종목은 비교 가능한 표, 안내·오류는 눈에 띄지만 차분한 상태 패널로 구분한다.
- 금융 광고용 hero, CTA 중심 랜딩 페이지, 자동 재생 애니메이션, 과도한 blur·glow·그림자는 사용하지 않는다.

### 접근성과 신뢰

- 가상투자 여부, 가격 출처, 평가 기준일, 계산 불가 사유를 화면에서 숨기지 않는다.
- 충분한 색 대비, 키보드 focus 표시, 논리적인 heading 순서, 명확한 표 제목을 제공한다.
- 외부 폰트·이미지·아이콘 CDN을 기본값으로 쓰지 않는다. 한글 system font stack과 CSS로 먼저 해결한다.
- 화면의 실제 데이터와 예시·개발 검증 데이터는 혼동되지 않게 표시한다.

## 구현 제약

- 웹 스택은 Django + Django Template + Django static CSS를 유지한다.
- 새 프론트엔드 프레임워크, CSS 라이브러리, icon library, 외부 CDN은 작업 문서가 명시적으로 허용하지 않는 한 추가하지 않는다.
- 화면 GET은 읽기 전용이다. 화면을 보기 위해 가격 수집, 주문 체결, 계좌 초기화, 원장 쓰기를 시작하지 않는다.
- 디자인 참고 문서는 구현 권한이 아니다. 각 T-XXX 작업 문서의 범위, 데이터 계약, 완료 기준이 이 문서보다 우선한다.
