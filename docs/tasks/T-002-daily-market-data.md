# T-002 pykrx 기반 국내 주식 일봉 데이터 수집

## 목표

증권 계좌나 API 키 없이 `pykrx`의 공개 일봉 OHLCV 조회를 사용해, 사용자가 지정한 국내 종목 한 개와 기간의 가격 데이터를 PostgreSQL에 저장하고 조회할 수 있게 한다. 이 데이터는 이후 가상 주문의 다음 거래일 시가 체결과 수익률 계산의 입력값이다.

## 승인한 데이터 출처와 전제

- 이 작업의 유일한 데이터 수집 수단은 Python 패키지 `pykrx`다. `pykrx`는 KRX와 Naver 데이터를 스크래핑하는 라이브러리이며, 제공처 약관을 지키고 무분별한 호출을 하지 않는다. 참고: https://github.com/sharebook-kr/pykrx
- `stock.get_market_ohlcv(fromdate, todate, ticker, adjusted=False)`로 일봉만 수집한다. `adjusted=False`를 명시해 수집 시점의 비조정 가격임을 저장한다.
- 종목 전체 수집, 반복 스케줄러, 실시간·장중 시세, KRX 로그인 정보, KIS·다른 증권사 API, 다른 웹 크롤링은 이 작업에 포함하지 않는다.
- 공개 OHLCV 조회가 추가 로그인·쿠키·인증을 요구하거나 정상 응답하지 않으면 이를 우회하지 않는다. 실제 호출 검증 결과와 막힌 원인을 인수인계에 기록하고 Codex에 보고한다.

## 구현 범위

### 1. 설정과 문서

- `.env.example`과 `docs/ENVIRONMENT.md`에 T-002의 설정 규칙을 반영한다.
  - `MARKET_DATA_PROVIDER=pykrx`를 로컬 설정값으로 사용한다.
  - 이 작업에서는 `MARKET_DATA_BASE_URL`, `MARKET_DATA_API_KEY`, `MARKET_DATA_API_SECRET`, `MARKET_DATA_REQUESTS_PER_MINUTE`를 비워 두며 읽거나 로그에 남기지 않는다.
  - `MARKET_DATA_PROVIDER`가 비어 있거나 `pykrx`가 아니면 수집 요청을 보내지 않고, 비밀값을 포함하지 않는 설정 오류로 끝낸다.
- `backend/app/config.py`의 시장 데이터 설정 판정은 API 키·endpoint가 필요한 제공처를 전제로 한 기존 조건을 그대로 쓰지 않는다. T-002의 `pykrx` 설정 여부를 정확히 표현하도록 최소 수정한다.
- README에 수집 API의 목적, 실행 전 `MARKET_DATA_PROVIDER` 설정, 제한 사항, 테스트 방법을 추가한다. 이 출처는 참고용이며 투자 조언이나 수익 보장을 제공하지 않는다는 점을 적는다.

### 2. 저장 구조

- 마이그레이션 프레임워크는 추가하지 않는다. PostgreSQL에 재실행해도 안전한 최소 스키마 초기화 방식을 사용한다.
- `daily_prices`에는 최소한 아래 값을 저장한다.
  - 종목 코드, 거래일, 시가·고가·저가·종가, 거래량
  - 데이터 출처, 비조정 가격 여부, 수집 기준 시각, 수집 실행 식별자
  - `(종목 코드, 거래일)` 유일 제약
- `market_data_collection_runs`에는 수집 실행별로 아래 값을 저장한다.
  - 실행 식별자, 출처, 종목 코드, 요청 시작·종료일, 수집 기준 시각
  - 원본 DataFrame을 결정적으로 직렬화해 계산한 SHA-256 해시, 반환 행 수, 성공·부분 성공·실패 상태와 안전한 실패 사유
- 가격·거래량은 부동소수점이 아닌 정수형으로 저장한다. 전체 연결 문자열, 인증값, 원본 응답 전문은 저장하거나 로그에 남기지 않는다.

### 3. 수동 수집과 조회 API

- backend에 다음 두 API만 추가한다. frontend는 변경하지 않는다.
  - `POST /market-data/daily-prices/collect`: 본문으로 `ticker`, `from_date`, `to_date`를 받아 한 종목·기간을 수집하고 저장한다.
  - `GET /market-data/daily-prices`: `ticker`, `from_date`, `to_date`의 저장된 데이터를 거래일 오름차순으로 반환한다. GET 요청은 외부 수집을 시작하지 않는다.
- 종목 코드는 숫자 여섯 자리, 날짜는 ISO `YYYY-MM-DD`, 시작일은 종료일보다 늦지 않아야 한다.
- 잘못된 입력은 422, 시장 데이터 설정 문제는 외부 요청 없이 명시적인 오류, 외부 조회 실패는 안전한 실패 응답으로 처리한다. 오류·로그·응답에는 환경변수 값이나 비밀값을 포함하지 않는다.
- 수집 결과에는 종목, 요청 기간, 출처, 비조정 여부, 수집 기준 시각, 원본 해시, 반환·삽입·갱신·제외 행 수를 반환한다.

### 4. 데이터 품질과 적재 규칙

- 반환한 날짜가 요청 기간 안에 있는지, 중복 거래일이 없는지 검사한다.
- 시가·고가·저가·종가는 양수여야 하며 `저가 <= 시가/종가 <= 고가` 관계를 검사한다. 거래량은 0 이상이어야 한다.
- 비거래일은 반환 행이 없을 수 있으므로 오류로 추정하지 않는다. 반면 0 가격, 잘못된 OHLC 관계, 기간 밖 날짜는 제외하고 그 건수와 이유를 실행 기록에 남긴다.
- 같은 `(종목 코드, 거래일)`을 다시 수집하면 중복 행을 만들지 말고 가격·출처·수집 기준 시각·수집 실행 식별자를 갱신한다.
- 유효 행이 하나도 없으면 가격 행을 적재하지 않고 실행 결과를 부분 성공 또는 실패로 명확히 남긴다.

- 종목명·시장 마스터, 전 종목 일괄 적재, 백테스트, 배당·액면분할 등 기업행동 처리
- 실시간 시세, 장중 데이터, 예약 수집·작업 큐·캐시

## 구현 제약

- AGENTS.md, docs/PROJECT_SPEC.md, docs/ENVIRONMENT.md, `skills/market-data-collector/SKILL.md`를 따른다.
- `pykrx`는 필요한 최소 의존성으로만 추가하고, 실제 설치된 버전은 `backend/requirements.lock.txt`에 반영한다. 설치 전에 버전을 추측해 고정하지 않는다.
- 제공처 endpoint, API 키, 로그인 정보, 요청 제한을 코드에 직접 쓰지 않는다. T-002는 `pykrx` 패키지 호출만 사용하며 직접 HTTP 요청을 만들지 않는다.
- 설정·수집·DB 접근 코드는 backend에만 둔다. 한국어 주석이 필요할 때만 작성하고, 비밀값을 주석에 쓰지 않는다.
- 하나의 승인된 제공처만 구현한다. 제공처 추상화·플러그인 구조를 만들지 않는다.
- 수집 테스트는 `pykrx` 호출을 mock 처리한다. 자동 테스트가 실제 KRX·Naver에 네트워크 요청을 보내면 안 된다.

## 완료 기준

1. `MARKET_DATA_PROVIDER=pykrx`일 때만 수집이 가능하고, 빈 값·다른 값에서는 외부 요청 없이 안전하게 실패한다.
2. 지정한 한 종목·기간의 일봉 OHLCV를 `pykrx`에서 가져와 `daily_prices`에 저장할 수 있다.
3. 각 수집 실행의 출처, 수집 기준 시각, 원본 해시, 반환·제외 행 수와 상태가 `market_data_collection_runs`에 남는다.
4. `(종목 코드, 거래일)` 중복 없이 재수집 시 기존 행이 갱신된다.
5. 입력 형식, 기간, 데이터 중복·누락·OHLC 관계·0/음수 가격을 검증하고 검증 결과를 숨기지 않는다.
6. 저장된 가격은 GET API로 거래일 오름차순 조회되며, 조회 API가 외부 수집을 시작하지 않는다.
7. 실제 주문·계좌·KIS·실시간 수집·스케줄러·frontend 변경이 추가되지 않는다.
8. 기존 `/health` 동작이 유지된다.
9. mock 기반 backend 테스트와 기존 테스트가 통과하고, 실제 네트워크 호출 여부는 별도로 명시한다.
10. README, 환경변수 문서, `docs/handoffs/T-002-claude-handoff.md`에 필요한 사용법·증거·제한이 기록된다.
