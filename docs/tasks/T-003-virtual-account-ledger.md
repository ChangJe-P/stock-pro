# T-003 가상계좌와 현금 원장 기반

## 목표

주몽의 단일 로컬 사용자가 실제 돈 없이 가상 현금으로 학습을 시작할 수 있도록, 최초 가상계좌·거래 가정·변경 불가능한 현금 원장을 backend에 만든다. 이 작업은 이후 가상 주문의 다음 거래일 시가 체결과 손익 계산이 참조할 신뢰 가능한 출발점이다.

## 이번 작업의 고정 가정

아래 값은 실제 증권사 수수료나 법정 세율을 주장하는 값이 아니다. 주몽 MVP의 학습용 시뮬레이션 정책 버전 v1이며, 사용자가 나중에 정책 변경 작업을 승인하면 새 정책으로 갱신한다.

| 항목 | v1 값 | 의미 |
|---|---:|---|
| 시작 가상 현금 | 10,000,000 KRW | 최초 계좌에 한 번만 적립하는 학습용 현금 |
| 매수 수수료율 | 0.015% | T-004 이후 매수 체결 금액에서 계산할 가정 |
| 매도 수수료율 | 0.015% | T-004 이후 매도 체결 금액에서 계산할 가정 |
| 매도 세금율 | 0% | 현 단계에서는 세금 계산을 적용하지 않는다는 명시적 가정 |
| 슬리피지 | 0 bps | 현 단계에서는 체결 가격 미끄러짐을 적용하지 않는다는 명시적 가정 |
| 정책 버전 | v1 | 계좌에 저장할 가정 식별자 |

- 실제 가격의 등락은 T-002가 저장한 일봉 가격을 이후 작업에서 사용한다. 위 값은 거래 비용 모델의 가정일 뿐 가격 수익률을 인위적으로 바꾸지 않는다.
- 실제 증권사·상품·시점별 수수료와 세금은 다를 수 있다. T-004 전에 실제 값처럼 보이게 표현하거나 투자 조언으로 설명하지 않는다.

## 구현 범위

### 1. 설정과 문서

- backend 설정 계층에 아래의 비밀값이 아닌 시뮬레이션 설정을 추가한다. 서비스 코드·테스트 fixture에 값 자체를 직접 적지 않는다.

| 변수 | T-003 로컬 값 |
|---|---|
| VIRTUAL_INITIAL_CASH_KRW | 10000000 |
| VIRTUAL_BUY_FEE_RATE | 0.00015 |
| VIRTUAL_SELL_FEE_RATE | 0.00015 |
| VIRTUAL_SELL_TAX_RATE | 0 |
| VIRTUAL_SLIPPAGE_BPS | 0 |
| VIRTUAL_TRADING_POLICY_VERSION | v1 |

- .env.example과 docs/ENVIRONMENT.md에 변수의 목적, 학습용 가정이라는 점, 값 변경 시 기존 계좌에는 소급 적용되지 않는다는 점을 기록한다.
- 각 값은 backend 설정 계층에서만 읽는다. 누락, 형식 오류, 음수 현금, 음수 비율, 1 이상 수수료·세금율, 음수 슬리피지는 안전한 설정 오류로 처리한다.
- 설정값은 비밀값이 아니어도 전체 DB 연결 문자열이나 비밀값과 함께 로그·응답에 노출하지 않는다.

### 2. 저장 구조

T-002와 같은 재실행 안전한 최소 PostgreSQL 초기화 방식을 사용한다. 새 의존성, 마이그레이션 프레임워크, 다중 사용자 모델을 추가하지 않는다.

- virtual_accounts 테이블
  - DB가 생성한 계좌 식별자, 생성 시각, 정책 버전
  - 최초 가상 현금, 매수·매도 수수료율, 매도 세금율, 슬리피지 bps의 정책 스냅샷
  - 단일 로컬 계좌만 존재하도록 DB 수준에서 보장한다.
- cash_ledger_entries 테이블
  - DB가 생성한 원장 식별자, 계좌 식별자, 생성 시각, 원장 유형, KRW 정수 금액, 안전한 설명
  - 최초 계좌 생성 시 opening_balance 유형의 양수 행 한 개를 기록한다.
  - 금액은 bigint 정수로 저장한다. 부동소수점 현금, 잔액을 별도로 저장해 갱신하는 구조, update·delete API를 만들지 않는다.

현재 사용 가능 현금은 opening_balance를 포함한 해당 계좌 원장 금액의 합으로 조회한다. T-003에는 주문·체결 원장 유형을 미리 만들지 않는다.

### 3. API

backend에 아래 API만 추가한다. 모든 응답은 실제 돈·계좌·주문과 무관한 가상 학습 계좌임을 명확히 표현한다.

- POST /virtual-account/initialize
  - 계좌가 없으면 설정 스냅샷으로 계좌 한 개와 opening_balance 원장 한 개를 원자적으로 생성한다.
  - 계좌가 이미 있으면 새 원장 행을 만들거나 기존 현금을 재설정하지 않고, 기존 계좌 조회 결과를 반환한다.
  - 설정 오류는 외부 요청·DB 부분 기록 없이 명시적으로 실패한다.
- GET /virtual-account
  - 계좌 식별자, 생성 시각, 정책 버전, 정책 스냅샷, 최초 현금, 원장 합계로 계산한 available_cash_krw를 반환한다.
  - 계좌가 아직 없으면 명시적인 not found 응답을 반환한다.
- GET /virtual-account/cash-ledger
  - 현금 원장 행을 생성 시각 오름차순으로 반환한다.
  - 계좌가 아직 없으면 명시적인 not found 응답을 반환한다.

### 4. 테스트와 문서

- 설정값 유효성, 첫 초기화, 반복 초기화의 비재설정, 원장 합계, 계좌 없음 조회, 조회 정렬을 테스트한다.
- 자동 테스트는 외부 시장 데이터·실제 증권사·실제 계좌에 요청을 보내지 않는다.
- 기존 health와 T-002 시장 데이터 테스트가 계속 통과하는지 확인한다.
- README에 가상계좌 초기화·조회 방법, 가상 현금 경계, v1 가정과 제한을 추가한다.

## 제외 범위

- 실제 증권 계좌, 계좌번호, 로그인, 잔고 조회, 실주문, 자동매매
- 매수·매도 주문 생성, 다음 거래일 시가 체결, 주문 취소, 보유 수량, 손익·수익률 계산
- 실제 수수료·세금 자동 동기화, 투자 자문, 실시간 시세, 가격 수집 변경
- frontend 화면, Notion 내보내기, 다중 사용자·권한, 캐시·작업 큐
- 정책 변경·계좌 초기화·원장 수정 또는 삭제 API

## 완료 기준

1. 가상 현금과 모든 거래 가정이 backend 설정 계층에서만 읽히며, 누락·형식·범위 오류가 안전하게 처리된다.
2. 최초 초기화는 단일 가상계좌와 opening_balance 현금 원장 행을 원자적으로 한 번만 만든다.
3. 반복 초기화는 기존 계좌·정책 스냅샷·현금을 변경하거나 원장 행을 추가하지 않는다.
4. 계좌 조회는 원장 합계로 계산한 available_cash_krw와 적용된 정책 스냅샷을 반환한다.
5. 원장 조회는 생성 시각 오름차순이며 수정·삭제 경로가 없다.
6. 실제 계좌·주문·체결·보유 수량·손익·가격 수집·frontend·Notion 기능이 추가되지 않는다.
7. 기존 health와 T-002 테스트를 포함한 backend 테스트가 통과한다.
8. README, 환경 문서, docs/handoffs/T-003-claude-handoff.md에 설정·테스트·제한이 기록된다.
