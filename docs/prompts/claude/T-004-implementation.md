## 구현 요청

T-004 작업 문서의 완료 기준을 만족하도록 backend를 구현해줘.

- 가상 **매수** 주문 생성, 주문 목록 조회, 주문 하나의 수동 체결 시도만 구현한다.
- T-002의 `daily_prices`에서 결정 거래일보다 엄격히 뒤인 첫 비조정 일봉 시가를 찾아 체결한다. GET·체결 모두 pykrx·HTTP·수집 API를 호출하지 않는다.
- T-003 계좌의 정책 스냅샷을 사용해 문서의 슬리피지·수수료 올림 규칙을 적용한다. 금액 계산은 결정적 정수/Decimal 산술로 하고 binary float로 금액을 계산하지 않는다.
- 성공 체결은 주문 상태와 음수 `buy_execution` 현금 원장을 한 트랜잭션에서 정확히 한 번 기록한다. 계좌 잠금과 주문별 원장 유일성을 사용해 동시 체결·재호출로 현금이 중복 차감되거나 음수가 되지 않게 해줘.
- 다음 거래일 가격이 없으면 pending을 유지하고, 현금 부족이면 원장 없이 종료 상태를 남겨줘. 이미 종료된 주문을 다시 체결하면 기존 결과만 반환해줘.
- 가격 출처·비조정 여부·수집 실행 식별자와 체결 기준가·체결가·총액·수수료를 주문에 보존해줘.
- 기존 health, 시장 데이터, 가상계좌 API와 테스트를 깨뜨리지 마. 새 환경변수·의존성·마이그레이션 프레임워크·frontend 변경은 추가하지 마.
- 하드코딩 금지 규칙을 지키고, 설명이 필요한 코드 주석은 한글로 작성해줘. 비밀값·DB 연결 문자열·환경변수 값 전체를 코드·로그·응답·문서에 넣지 마.

## 테스트와 인수인계

- 자동 테스트는 DB·pykrx·네트워크를 mock 처리하고, T-004의 성공·가격 부재·현금 부족·반복 체결·같은 날 누수 방지·수수료/슬리피지 규칙을 검증해줘.
- 가능하면 로컬 PostgreSQL에서 주문·원장·현금 합계가 실제로 일관되는지 별도 확인하되, mock 테스트와 실제 DB 확인을 섞어 쓰지 마.
- `README.md`에 가상 주문 생성·수동 체결 순서, 다음 거래일 시가 원칙, 매수 전용·대기 현금 미예약·실제 투자 아님을 반영해줘.
- `docs/handoffs/CLAUDE_HANDOFF_TEMPLATE.md` 형식으로 `docs/handoffs/T-004-claude-handoff.md`를 작성해줘. 변경 파일 전체, 요구사항별 위치, 실행 명령·결과, mock/실DB/외부 네트워크 검증 구분, 가정·제한·미해결 항목을 빠짐없이 적어줘.
- 논리적으로 나눈 커밋을 만들되, **push·PR 생성·병합은 하지 마.** 완료 후 최종 커밋 해시와 인수인계 파일 경로를 알려줘.
