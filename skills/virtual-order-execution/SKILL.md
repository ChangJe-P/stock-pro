# 주몽 가상 매수 주문·다음 거래일 시가 체결

## 목적

학습용 매수 판단을 주문으로 남기고, 결정 거래일보다 뒤의 첫 저장 일봉 시가로만 체결한다. 이는 같은 날 종가를 보고 같은 날 체결하는 미래 데이터 누수를 막기 위한 규칙이다.

## 시작 전 확인

- 현재 작업 문서에 주문 유형, 결정 거래일, 체결 가격·비용 공식, 상태 전이, 실패 시 원장 처리 규칙이 있는지 확인한다.
- T-002의 저장 일봉과 T-003의 단일 가상계좌·추가 전용 현금 원장을 재사용한다. 가격을 새로 수집하거나 실제 계좌·증권사 API를 호출하지 않는다.
- 작업 브랜치가 작업 문서의 브랜치와 같은지 확인한다.

## 고정 규칙

- 이 단계는 매수만 다룬다. 보유 수량 검증 없는 매도, 주문 취소·수정, 현금 예약, 자동 실행은 별도 작업이다.
- 주문 생성은 결정일의 저장된 비조정 일봉 존재만 확인하며 현금을 차감하지 않는다.
- 체결 후보는 `trade_date > decision_trade_date`인 저장 일봉 중 가장 이른 한 행이다. 같은 날 가격·종가·외부 조회를 사용하지 않는다.
- 비용 가정은 계좌에 저장된 정책 스냅샷에서 읽는다. 가격·수량·수수료·현금은 정수로 저장하고, 금액 계산에는 binary float를 쓰지 않는다.
- 체결 성공의 주문 상태 변경과 음수 현금 원장 추가는 한 트랜잭션에서 처리한다. 계좌 행 잠금과 주문별 원장 유일성을 사용해 중복 체결·음수 현금을 막는다.
- 가격이 없으면 `pending`을 유지한다. 현금이 부족하면 현금 원장 없이 종료 상태를 남긴다. 종료 주문 재실행은 기존 결과만 반환한다.
- 체결 주문에는 선택한 가격 행의 거래일·출처·비조정 여부·수집 실행 식별자와 계산 결과를 보존한다.

## 검증

- 결정일보다 엄격히 뒤인 첫 거래일 시가만 쓰는지, 같은 날 가격을 쓰지 않는지 확인한다.
- 체결 성공·현금 부족·가격 부재·반복 실행에서 주문 상태, 원장 행 수, 원장 합계가 각각 기대대로인지 확인한다.
- mock 테스트, 실제 PostgreSQL 확인, 실제 외부 네트워크 확인을 구분한다. 이 작업에서 외부 가격 요청은 필요 없으므로 자동 테스트가 이를 시작하면 실패다.

## 제외

- 매도·보유 수량·손익·수익률, 실제 계좌·실제 주문·자동매매
- 실시간 가격, 스케줄러·큐, 가격 수집 변경, frontend, Notion·다중 사용자 기능
